## RestFul API

#### 什么是Restful 架构？

1. 每一个URI代表一种资源；
2. 客户端和服务器之间，传递这种资源的某种表现形式比如 `json`、`xml`、`image`、`txt` 等等；
3. 客户端通过特定的 HTTP 动词，对服务器端资源进行操作，实现“表现层状态转化”。  

#### Restful API 规范有哪些？  

动作：  
- `GET`：请求从服务器获取特定资源
- `POST`：在服务器上创建一个新的资源
- `PUT`：更新服务器上的资源（客户端提供更新后的整个资源）
- `DELETE`：从服务器删除特定的资源
- `PATCH`：更新服务器上的资源（客户端提供更改的属性，可以看作是部分更新），使用较少。  

路径：  
- 网址中不能有动词，只能有名词，API中的名词也应该使用复数。不过，若API调用并不涉及资源的话，可以用动词。  
- 不同大写字母，建议用中杠`-`，不用下杠`_`。
- 善用版本化API。当API发生重大改变而不兼容前面版本的时候，可以通过URL来实现版本化，比如`http://api.example.com/v1`
- 接口尽量使用名词，避免使用动词。


# 认证授权

## 基础概念

#### 认证和授权的区别是什么？  

- 认证（Authentication）：身份/用户认证
- 授权（Authorization）：发生在认证之后，主要是掌管访问系统的权限。

#### RBAC模型了解吗？  

系统控制最常采用的访问控制模型就是RBAC模型。   

RBAC 即基于角色的权限访问控制（Role-Based Access Control），是一种通过角色关联权限，角色同时又关联用户的授权的方式。   
一个用户可以拥有若干个角色，每个角色又可以有若干个权限。在这种模型中，用户与角色、角色与权限之间构成了多对多的关系。   

通常来说，如果系统对于权限控制要求比较严格的话，一般会选择使用 RBAC 模型来做权限控制。  

#### 什么是Cookie？Cookie的作用是什么？

Cookie 存放在客户端，一般用来保存用户信息。
